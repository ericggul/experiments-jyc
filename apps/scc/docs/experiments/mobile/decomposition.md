# Decomposition — /mobile/transform/decomposition/[clone]

Experimental, 2026-10-03. The baseline is each preserved `clone/1`–`clone/13` surface. The tested relation is the interface's part–whole hierarchy: a screen groups unlike parts by item (class row > time, title, studio, rating); decomposition takes it apart into atoms and transposes it, so every time sits with every time, every ★ with every ★, every rating with every rating. The bottom-right control is collapsed to one button showing the state (분해, 원본, or 분해 0.50) and expands into a panel: 원본 / 분해 (animated; 분해 is the entry state), a 위치 slider from 0 (original place) to 1 (category place), and 이동 선, which draws each atom's line from its original centre to its sorted centre above the interface. A line is dark from its start to where its atom is now and light (20 %) beyond, so at 0.3 the first 30 % of every line is dark; its thickness grows with the atom's size (√area, 0.5–5 px, so a photograph draws a bar and a glyph a hairline). Arrowheads, end rings, position dots, and legend marks were tried the same day and removed as decoration. 곡선 switches every route, and every piece's motion, from the straight segment to a parabolic arc: a quadratic Bézier (in cubic form) bending once, its apex pushed from the chord's midpoint by 30 % of the distance toward the top of the screen (a vertical move bends right). A first version used a vertical-tangent S-curve, which bent twice and was replaced. The piece's centre is the Bézier point at t and the drawn curve is split there by de Casteljau, so the dark part still ends at the piece; scale stays linear. Line colour is set explicitly (black, or white on a dark backdrop); an earlier build inherited `currentColor`, which turned near-white under the dark `prefers-color-scheme` body colour and hid the lines. The control sits in the bottom-right corner (16 px). Every atom rests at the slider's value along the straight segment between its two places, so at 0.5 it sits halfway along its drawn line; a reversal mid-flight continues from where the atoms are.

The first version (same day) lifted whole action targets. Because a class row or product card is one button, it reproduced the original layout almost unchanged and was replaced.

## Method

The engine (`components/mobile/transform/decomposition/engine.ts`) knows nothing about the clones and can be mounted beside any page.

1. **Atoms** (`collect.ts`): one text node (React's `"50" "min"` are two), one icon/image/video/canvas, one form field, or one element's own fill, border, or shadow without its contents (boxes over half the viewport are left out). Only the interface in front is collected: a fixed/absolute element covering most of the viewport under its centre (a modal backdrop, comment sheet) replaces the page behind it.
2. **Categories** (`category.ts`, structural by default): each element's key is its parent's key plus tag, first class, and role, computed top-down. Same-signature siblings merge as a list (rows, chips, days) unless the parent's key recurs and most recurrences hold the same number of them, which marks fixed roles (the three unclassed lines in every row) that keep their index. A text atom adds its text-node index, a box atom `#box`; icons are keyed by their drawing, so every heart in the app gathers together. The strategy is an option, so a semantic reading can be added later.
3. **Copies** (`snapshot.ts`): text gets its parent's computed type and colour; boxes their fill, border, and shadow; graphics and fields a deep clone with computed properties frozen inline. Ink that would vanish on the backdrop keeps the colour it sat on, or the opposite neutral when it sat on a photograph.
4. **Layout** (`layout.ts`, pure): one continuous packed flow, 4 px apart, like words in a paragraph. Categories follow each other in first-appearance order and atoms within one in document order, so the *n*th atom of every category belongs to the same item; a category starts on the same line where the previous one ended and wraps only when the width runs out. (The first atomic version started every category on a new line with a 24 px gap.) Categories of large shapes or images become grids of up to three columns; text keeps its size.
5. **Motion** (`pose.ts`, pure): each atom has a home pose (its place in the live page, in stage coordinates) and a sorted pose; position, scale, and therefore centre interpolate linearly, so the centre travels exactly along the drawn segment (one dark and one light SVG path per thickness, above the pieces). Every piece carries its own progress t; buttons tween each t on one requestAnimationFrame loop (staggered by category), and the slider sets all t directly, so the dark part of each line always ends exactly where its piece is, mid-animation included. A re-sort under resting pieces still glides with Web Animations. At 0 the copies reproduce the page with inner scroll areas unclipped; only 원본 hands the live page back. Every visible part of the page is an atom, so the page is hidden as a whole while the copies are shown, and swapped back when they land. Each sync reads all positions before writing anything.

The page stays live underneath (`forward.ts`). A click on an atom clicks its source element (bubbling to the button it was part of); typing, select changes, Enter, and focus are forwarded so controlled inputs update. Any DOM change re-collects: changed atoms are re-copied, new screens and modals fly in from their own positions, and atoms that left fade.

## Precedents

[Ursus Wehrli, *Tidying Up Art*](https://www.ted.com/talks/view/id/400) is the closest: paintings and everyday scenes sorted by kind. [Brad Frost's interface inventory](https://bradfrost.com/blog/post/interface-inventory/) is the same operation in UI practice, made for design-system work; [Jenny Odell's *Satellite Collections*](https://creativebloq.com/art/collage-art-created-google-maps-satellite-collections-7133616), [Christian Marclay's *Telephones*](https://publicdelivery.org/christian-marclay-telephones/), and [Arman's *Accumulations*](https://www.theartstory.org/amp/artist/arman/artworks/) gather one kind out of many contexts. [Rafaël Rozendaal's *Abstract Browsing*](https://www.vice.com/en/article/turn-your-web-browsing-into-abstract-art) keeps a transformed page clickable.

## Status and limits

Headless Chrome at 390×844 (2026-10-03): on `/9` (Rep) times, AM/PM, durations, titles, studios, neighbourhoods, instructors, ★, ratings, review counts, and credit numbers each form one row; tapping the copied `26` changed the source to Saturday, Sep 26 and the decomposition re-sorted; returning reassembled the page with no leftover overlay or hidden attributes. `/1` and `/11` were also checked; on `/11` tapping a copied comment icon decomposed only the comment sheet. On `/11` (2,044 atoms) entering produced one 121 ms long task and returning none, after moving all reads ahead of writes (before: 1,994 ms and 800 ms). Slider and lines: on `/9` the lines join original and sorted centres, 0.5 places atoms midway, 0 reproduces the page, and 원본/분해 still hand the live page back and forth; on `/11` stepping the slider across 2,044 atoms produced no long task; closing with routes on ran at a 17 ms median frame with one 183 ms frame (headless desktop Chrome). No real phone has been tested. Not forwarded: swipes, long presses, pointer drags. A bottom sheet without a full-viewport backdrop is decomposed together with the page behind it; pseudo-element decoration is not an atom; WebGL canvases may copy blank.
