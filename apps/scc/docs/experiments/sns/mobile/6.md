# THREAD — mobile/6

Experimental fictional British fashion resale marketplace at `/sns/mobile/6`, added 2026-09-23. Independent model, React screen and CSS Module preserve mobile/1–5. The baseline architecture is mobile/1 and mobile/5; presentation is a new UK resale surface, not their translated skin.

The revised catalogue uses a 58px toolbar with a restrained lowercase wordmark, one search field and one results/filter row. Category, size and sort controls move into an accessible native sheet. Two-column 4:5 photographs lead each listing, followed by 13–14px title/size/condition and a 16px GBP price; seller information appears in the item detail instead of repeating avatars above every tile. UK sizes, London seller wardrobes and one-off inventory preserve the service context. Desktop keeps a 480px app width; the scroll surface and bottom navigation account for safe areas. Primary purchase and selected navigation actions use a restrained dark teal.

## Interaction contract

- Search title, brand, seller or neighbourhood; filter category/UK size; sort picks, newest or price.
- Hearts collect saved items; seller handles filter their wardrobe. Native item dialogs support keyboard dismissal and independent saving.
- Each listing is one available item. Repeated add opens the bag; removals update totals. Tracked delivery is £3.49 per distinct seller, grouping items by wardrobe.
- Checkout validates required delivery fields and UK postcode, discloses fictional/local-only behaviour before submission, then saves an order for the current visit. No real payment or contact occurs. Purchased listings leave available browse results and cannot be bought again during that visit. Purchases retain accessible item details.
- State lives in React for this visit only. The checkout requests made-up details; no network submission or persistence occurs.

## Visual reference and limits

The user viewed the first implementation and rejected it as unprofessional and “ai slop” on 2026-09-23. Its squeezed red wordmark, five stacked browse strips, repeated seller avatars and tiny metadata were removed. This is a substantive composition and legibility rework, not a claim that the original design succeeded.

For the rework, inspected [an actual Vinted UK product-results screenshot](https://skinnyspending.co.uk/wp-content/uploads/2023/07/Vinted-price-examle.jpg) from [Skinny Spending's Vinted guide](https://skinnyspending.co.uk/how-to-sell-on-vinted). The 600 × 1200 image contains a phone frame with an approximately 440px-wide white app aperture: compact grey search, plain filter controls, two tall clothing images with narrow gutters, GBP prices and size/brand immediately below, restrained outline navigation icons and teal action states. THREAD takes the image-led grid, plain control treatment and readable listing hierarchy; filter consolidation is a deliberate fictional adaptation. Device chrome and article annotations are not reproduced. No pixel-fidelity claim is made.

The rejected first pass had been informed by [a Depop mobile home screenshot](https://hips.hearstapps.com/hmg-prod/images/depop-guide-interface-1664445606.png?resize=980%3A%2A). Its photographic density alone did not resolve the first implementation's typography and composition.

Product photography uses remote Unsplash URLs in the local model, with no new image dependency. Listings and sellers are fictional. No live stock, external seller communication or shipping integration exists.

Verification: scoped static checks and source review only. No browser/runtime or responsive rendering verification was performed under the repository runtime restriction. Scoped TypeScript validation passed after the rework. Remote photo loading and final rendered 320–480px layout remain unverified. Product photos are retained stock sources rather than a newly commissioned coherent resale wardrobe; this remains a material fidelity limit.
