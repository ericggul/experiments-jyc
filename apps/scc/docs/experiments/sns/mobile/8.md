# PLATFORM — mobile/8

Experimental British rail booking surface at `/sns/mobile/8`, added 2026-09-23.
Independent model, React screen, CSS Module and index; no changes to 1–5.
The existing mobile/3 connected search/detail/booking flow was inspected as an
architectural baseline, but its editorial lodging composition was not reused.

## Visual reference and adaptation

Direct official reference inspected before implementation:
[Trainline affiliate image](https://www.thetrainline.com/cmsmedia/cms/8795/grow-fast.jpg),
from [Trainline's affiliate page](https://www.thetrainline.com/es/afiliaciones).
The downloaded 1000×667 image contains two angled phones. The left search
aperture is roughly 300px across, starting around x=245/y=162; its navy header
contains stacked lighter station fields and an overlapping swap control. The
white form uses compact rows with left labels/right dates, passenger and
Railcard selectors, and a nearly full-width green search button at the bottom.
The right phone shows compact outbound rows: strong departure/arrival times,
small station and journey text, and right-aligned GBP fares. Device shells,
reflections, promo background, scarcity claims and status-bar chrome were not
copied. No assets from that image are shipped.

PLATFORM fictionally adapts that search-to-timetable grammar, not a claimed
pixel copy or current Trainline version. Navy contains the active route;
white rows prioritise dates and stations; green identifies booking actions.
Arial, restrained 11–16px supporting type and larger tabular times keep the
app utilitarian. Timetable connecting lines encode elapsed journey time;
ticket headers and route lines encode bookings and station order. No generic
hero, photo cards, artificial live states or ornamental badges.

## Behaviour

- Search and swap London King’s Cross, York and Edinburgh Waverley; station
  filtering, singles/returns, date/time inputs, 1–6 adults, one 26–30 Railcard.
- Six deterministic sample departures after the requested time, stopping before
  21:00. Sort by departure, fare or duration; direct-only filter; empty state.
- Outward and return selection, journey details and two fare choices. Return
  options must depart after outward arrival; changing the outward selection
  clears the prior return. Search edits clear both selections on submission.
- GBP totals multiply passengers and discount only one adult with the Railcard.
  This simplified sample discount/fare policy is not a real operator policy.
- Checkout explains fictional operator, schedule and fares; affirmative local
  demonstration acknowledgement required. No payment data is requested.
- Session-only wallet, booking detail and confirmed sample cancellation.
  Tickets visibly state that they are not valid for travel. No barcode is issued.
- Native modal dialogs, semantic forms/buttons, focus indicators, disabled
  quantity bounds, safe-area navigation and 440px desktop containment. CSS
  includes a narrower layout for 320px; document remains normally scrollable.

Scoped ESLint passed on 2026-09-23. No browser/runtime inspection was performed;
320–480px geometry, physical keyboard behaviour and rendered fidelity remain
unverified. Parent integration owns the route/registry and complete typecheck.
