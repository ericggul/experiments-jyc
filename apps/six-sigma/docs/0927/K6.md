# K6 — 2026-09-27

Experimental mobile surface at `/mobile/0927/K6`, owned by
`components/mobile/0927/K6`. Black viewport, white edges, regular-hexagon
geometry, safe-area spacing, and the original responsive bounds remain fixed.
The bottom-right `edit` disclosure adapts the local gaze-tracking filter's
position, trigger, panel, and radio controls. Escape closes it and returns focus.

- **K6:** six vertices and fifteen edges. Static mode preserves the original graph.
- **Fractal K6 · opt 1:** approved recursive compound view. `F(0)` is a leaf;
  `F(d)` is K6 whose six nodes are `F(d-1)` objects. The displayed depth 2 has
  36 leaves, 90 child-level edges, and 15 parent-level relations. Parent edges
  reference entire child graphs and follow macro-centre axes to the child
  hexagon boundaries with a 2-unit clearance. No arbitrary child port or
  fabricated parent dot remains. A parent-level arrival briefly brightens the
  receiving miniature's internal K6 rather than enlarging one leaf. See the
  [recursion review](K6-recursion.md).
- **Fractal K6 · opt 2:** the same 36 leaf positions with every pair connected:
  90 internal + 540 inter-group = 630 edges, degree 35 at every leaf. This is
  `K6[K6]`, mathematically K36 with a recursive layout. Inter-group lines use
  a thinner 0.22px stroke to keep the dense field legible. All normal edges still
  share the selected Static/Flow opacity. Arrivals are at actual leaf nodes.
- **Static / Flow:** static edges have opacity 1; flow edges have opacity 0.5.
  Vertex dots remain white. A short white segment has a narrow black clearance
  so it remains distinguishable at crossings. Arrival briefly enlarges its
  destination leaf dot; compound arrivals use the whole miniature. No halo or glow.
- **Edge shape:** Straight keeps the initial geometry. Cubic Bezier bends each
  connection gently while retaining its exact endpoints; Flow signals follow
  the same cubic with distance-based travel rather than crossing it on a chord.
  Cubic Bezier directional (revised 2026-09-30) draws two lanes per
  connection. Each bends to the right of its own travel, so outgoing and returning
  curves mirror each other across the chord. A midpoint chevron marks each lane, and
  the drawing keeps the hexagon's symmetry. Signals take either direction and stay
  in that direction's lane. The earlier single, one-way curve bent by stored index
  order, which broke the symmetry. This selector applies to every K6
  and K3 graph mode. The 29,403-edge K3
  depth-5 topology remains in the existing bounded canvas renderer.
- **Flow rate:** 0.5–8 expected signals/second, initially 2.5. Exponential
  waiting times generate Poisson events, each choosing an edge uniformly and a
  direction with equal probability (in directional mode, the lane). Multiple signals can share an edge. The
  previous one-per-edge rejection rule is removed. Travel speed also changes
  by `sqrt(rate / 2.5)`, continuously for active signals, so higher settings
  increase both throughput and typical visible density. A 48-packet ceiling
  remains as an emergency bound. This is illustrative stochastic traffic, not
  measured information, conservation, or a financial model.

The triangle's bounding box is centred in the existing square field. Depths 4
and 5 retain all edges but draw their static topology into one DPR-1 canvas in
batches of at most 512 edges per 42 ms tick, only after a selection, weight
edit, or resize; there is no continuous topology redraw. The 48-SVG-packet Flow
pool remains separate. High depths are necessarily dense under opt 2's complete
leaf-to-leaf rule; the depth-5 static image can read as a filled triangular
field rather than individually traceable lines at mobile scale.

**Within-node / Inter-node weights** are available in every graph mode, 0–3
with neutral default 1. Within means both endpoints belong to the same one of
the top-level compound nodes; Inter means different top-level nodes. Both
scale their respective normal edge widths and stochastic edge-selection
weights. Zero hides the group's lines and excludes it from new signals;
existing signals finish. In basic K6, there are no compound children, so only
Inter applies and Within is disabled. Flow rate remains a separate control.

`model/k6.ts` preserves the base geometry; `model/fractal-k6.ts` and
`model/fractal-k3.ts` own nested graph construction; `model/types.ts` shares the
graph contracts. `edges/` contains line geometry and static SVG/canvas rendering;
`flow/` contains stochastic traffic and its bounded SVG renderer; `controls/`
contains the edit panel. The root `index.tsx` composes the surface. K6 travel
speed at the default rate is 104 SVG units/second; fractal uses 72 with a shorter trail for its local
edges. No predefined relay route remains. Random seeding occurs only after
hydration. A fixed SVG pool updates at most 24 Hz, pauses while hidden, stops in
Static mode, and cleans up on mode changes/unmount. Reduced-motion preference
restores the opaque static graph and stops the scheduler. No dependencies or
servers were added; the financial-network references remain untouched.

## Reference review

Search terms: `animated edge textures`, `directional particles`, `single-hop
particle emission`, `animating SVG elements along edges`. Sources consulted
2026-09-27; external demos were read as source, not browser-tested.

| Source | Useful rule and adaptation |
| --- | --- |
| [Romat et al., Animated Edge Textures, CHI 2018](https://aviz.fr/~bbach/papers/Romat2018animated.pdf) | Figure 1 distinguishes particle pattern, frequency, and speed. Keep frequency and speed conceptually separate; the revised control deliberately couples them to make a faster, denser flux. The paper's figure was visually inspected; its study does not validate this implementation. |
| [React Flow: Animating Edges](https://reactflow.dev/examples/edges/animating-edges) | A localized SVG object follows an edge while topology remains fixed. Retain SVG without importing the library; the bounded scheduler coordinates stochastic arrivals, trails, and receipts. |
| [Force Graph: emit-particles source](https://github.com/vasturiano/force-graph/blob/master/example/emit-particles/index.html) | Single-hop emissions provide a discrete event primitive. Combine independently timed events instead of a single looping object or uniformly marching dashes. |
| Local `financial-network/2/index.tsx` | Reveals/clears complete paths using dash offsets, with terminal arrows and labels appearing partway through. Code-based interpretation: this may read as edges appearing rather than payloads travelling. |
| Local `financial-network/5/index.tsx` | Encodes flow by whole-path width/opacity and static arrows; no along-edge transport. Code-based interpretation: rate variation alone does not show a transfer's passage. |
